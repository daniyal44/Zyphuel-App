Two open items

Firestore rules for the desktop console yours

The console reads Firestore over its REST API, because the Firebase SDK is Android-only. If your project's rules require an authenticated user, the console will show a clear HTTP 403 message instead of data. Allowing read — and write, for status changes — on the orders and live_tracking collections is what makes it work. Tell me which way you want it and I will wire the matching auth or rules.

Google Maps key optional now

You said you do not have one, and you no longer need one: the app falls back to its vector map, and both the live tracking map and the desktop console use tile sources that need no key. If you ever want native Google tiles, the key already sitting in app\google-services.json can serve — it needs “Maps SDK for Android” enabled on project ai-420, which requires a billing account.
